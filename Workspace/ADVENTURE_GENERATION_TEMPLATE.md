# ADVENTURE GENERATION TEMPLATE
## Pathfinder Society–Inspired Structure for an Image-Driven Adventure Generator

<!--
PURPOSE

Use this file as the structural template for generating a complete tabletop RPG adventure
from a supplied source image.

The source image is inspiration, not a literal requirement to reproduce every visible element.

The generated adventure should use the image to infer:
- location and environment;
- mood and tone;
- likely history;
- factions or inhabitants;
- obvious and hidden dangers;
- points of interest;
- possible objectives;
- potential conflicts;
- visual landmarks;
- opportunities for combat, social interaction, exploration, skills, hazards, puzzles, and discovery.

This template is inspired by the practical organisation of Pathfinder Society scenarios:
GM-facing overview -> background -> adventure summary -> opening briefing -> named adventure
sections -> conclusion -> encounter/stat-block appendices -> game aids.

Do not copy Pathfinder Society setting content, characters, prose, encounter text, maps,
or proprietary adventure material. Use only the high-level organisational approach.

DEFAULT TARGET:
- One-session adventure
- Approximately 4–5 hours of play
- 3–6 player characters
- Adjustable to the configured game system and party level

Remove all template guidance and placeholder text from the finished adventure.
-->

# APPENDIX G — ADVENTURE VALIDATION

## Structure

- [ ] Adventure premise is immediately understandable.
- [ ] GM Synopsis reveals the actual situation and major secrets.
- [ ] Adventure Background explains how the current situation arose.
- [ ] Adventure Summary accurately reflects the detailed sections.
- [ ] Getting Started gives the characters a clear reason to engage.
- [ ] Each major adventure section has a clear purpose.
- [ ] The finale resolves the main dramatic question.
- [ ] The conclusion covers success, partial success and failure.

## Image Use

- [ ] The adventure is recognisably inspired by the supplied image.
- [ ] Major image elements used in the adventure have a meaningful purpose.
- [ ] The generator has not forced irrelevant image details into the adventure.
- [ ] Invented details are compatible with what is visibly present unless intentionally supernatural or deceptive.

## Player Agency

- [ ] Major problems allow more than one credible approach where appropriate.
- [ ] Combat is not assumed to be the only valid solution unless the fiction requires it.
- [ ] Social, skill, stealth, exploration or creative options appear where credible.
- [ ] Meaningful choices create meaningful consequences.
- [ ] Earlier discoveries or choices can influence later scenes where appropriate.

## Failure and Robustness

- [ ] No single failed check prevents completion of the adventure.
- [ ] No single missed clue prevents completion of the adventure.
- [ ] Essential clues have multiple acquisition paths.
- [ ] Major failures create complications or alternate routes rather than dead ends where possible.
- [ ] The GM has guidance for players bypassing expected scenes.
- [ ] NPC death, capture or refusal does not accidentally break the adventure unless intentionally designed to do so.

## Encounters

- [ ] Every encounter has a narrative purpose.
- [ ] Opponents have goals and behaviour, not merely stat blocks.
- [ ] Combatants do not automatically fight to the death without reason.
- [ ] Terrain or environmental features matter in major encounters.
- [ ] Hazards and challenges fit the location and story.
- [ ] Encounter difficulty is appropriate for the configured party.
- [ ] Scaling guidance exists if scaling is required.

## Pacing

- [ ] The amount of content fits the requested session length.
- [ ] No single scene is likely to consume the entire session accidentally.
- [ ] Optional content can be omitted if time is short.
- [ ] The adventure contains escalation toward the finale.
- [ ] Exposition is distributed rather than delivered in one excessive block.

## Mechanics

- [ ] All referenced creatures, hazards, items and rules exist or are fully defined.
- [ ] All DCs / difficulties are appropriate for the configured system and level.
- [ ] Stat blocks are complete where original creatures or NPCs are created.
- [ ] Rules references are internally consistent.
- [ ] Rewards are appropriate for the system and adventure scope.

## Consistency

- [ ] NPC names and motivations are consistent.
- [ ] Location names are consistent.
- [ ] Timeline is internally consistent.
- [ ] Clues reveal the information claimed.
- [ ] The Adventure Summary matches the final adventure.
- [ ] Appendix references point to the correct encounter or aid.

---

# FINAL OUTPUT REQUIREMENTS

The completed adventure must:

1. Follow this structure unless a section is genuinely inapplicable.
2. Remove unused placeholders and template guidance.
3. Contain no empty headings.
4. Be runnable by a GM without needing to invent missing core content.
5. Separate GM-only secrets from player-facing information.
6. Provide enough information to adjudicate expected encounters.
7. Provide alternate approaches where they are credible.
8. Include fail-forward guidance for critical challenges.
9. Keep detailed stat blocks in the encounter appendix where practical.
10. Include a concise GM quick-reference section.
11. Be internally validated before final output.
12. Use the supplied image as meaningful inspiration rather than merely decorative flavour.

The final adventure should read as a complete, professionally structured scenario rather than
a collection of disconnected encounters.
